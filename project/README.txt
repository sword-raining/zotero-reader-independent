本次更新（0.14.24）
收紧设置页留白，将并发篇数、自动修订和修订次数合并为紧凑控制行，刷新分类按钮与监听分类同行；窄面板自动换行。

保留的更新（0.14.23）
新增一键清理重复 PDF 和修复已确认的附件归属。以文件内容和首页 DOI 核对，优先保留批注、笔记和原链接；安全重复副本移入 Zotero 回收站。
在批量附件窗口的“附件整理”使用。目标已有相同 PDF 时清理空副本；两份都有保护信息或内容不同则保留。只有唯一 DOI 匹配的已有题录可一键修复，不永久删除文件。270 项自动检查、22 项隔离原生检查通过。

保留的更新（0.14.22）
自动利用本地 PDF 文字和已有解析缓存识别正文、补充材料与版本；多个正文优先已发表版本，同级选择一份，保留手动改选。
识别使用 Zotero 本地提取前两页文字，不是视觉模型；已有有效解析缓存可复用。识别失败或扫描件无文字时沿用附件信息并标明来源，不为选正文上传 PDF。255 项自动检查、19 项隔离原生检查通过。

保留的更新（0.14.21）

按建议处理只作用于当前文献，显示新增/移出数量；其他已有分类保留。正文未定时点击定位，不自动猜选或默默跳过。246 项自动检查、32 项隔离原生检查通过。

保留的更新（0.14.20）

未完成的请求需重新执行；已有完整草稿继续检查，尚无完整初稿时重新生成该步。已保存笔记和人工修改稿保持原样。236 项自动检查、23 项隔离原生检查通过。

保留的更新（0.14.1）
此前概览页按钮为“清理生成缓存”（0.14.11 已合并为“清理已完成任务”）。固定说明明确：仅处理已成功保存到 Zotero 的笔记，清理生成它们时留下的 Markdown 草稿、核验中间文件和闲置解析缓存。原 PDF、已保存笔记、知识库文件不会删除；未导入或保存后又修改的稿件仍会保留。
新任务导入成功后自动清理，按钮用于补清旧任务或重试清理。操作结果单独显示，不覆盖上述说明；反馈文案明确清理的是缓存，而不是已导入的笔记。本次不改变清理规则。

保留的更新（0.14.0）
成功导入 Zotero 笔记后，自动清理本次本地 Markdown、结构化草稿、原文索引、核验过程及对应 CLI 调用目录，并清理没有被其他未完成任务使用的解析缓存。清理只在笔记事务提交且简短保存记录落盘后进行；失败时笔记仍有效，临时内容保留供重试。
尚未导入、核验未完成、导入失败的稿件不清理。导入后又被修改的 Markdown、额外加入的文件、仍被其他稿件使用的缓存会保留。原 PDF、已保存笔记及 Wiki 文件从不属于清理对象。设置概览页的“清理已完成任务”可一并处理已保存且已确认归档的历史任务，并保留修改稿及未完成记录。
最终笔记保留精读正文、必要的正文引用及原 PDF/所选补充材料链接，不再自动追加整段原文引句附录。完整证据仍用于核验，过程缓存沿用成功保存后的清理规则。笔记附带简短来源识别信息，包括条目 key、所读 PDF 指纹、导入状态等；不包含本机路径、数字 itemID、密钥或完整核验日志。识别信息还保留在 Zotero 编辑器支持的来源链接中，普通 HTML 格式整理不会使其丢失；PDF 链接仍定位原附件。
跨电脑只同步 PDF 和已导入笔记：PDF 沿用 Zotero 文件同步（包括个人文库的坚果云/WebDAV），笔记复用 Zotero 数据同步。本版不开发草稿、核验进度或解析缓存同步。
新电脑没有本地队列和缓存时，“查看精读结果”仍可找到已同步的精读笔记；批量和自动入口会核对新版笔记中的来源指纹，避免重复处理。PDF 尚未下载时，先等待文件，在真正处理前再次核对已有笔记。人为修改笔记内容后会识别为人工修改稿，不把旧 AI 检查结论套给新内容，也不覆盖修改。
旧版带精读标记的笔记仍可打开；缺少来源指纹时不声称已确认 PDF 版本，不能保证自动跳过所有旧版结果。主动重新精读仍保留新旧版本，本版尚未实现“一篇文献只保留一份主笔记”。
Windows 清理直接检查文件系统重解析点，拒绝沿符号链接或目录联接删除；若宿主无法确认路径属性，则保留临时内容。已验证离线回归及无界面 Zotero 的笔记事务/JSON 往返/来源链接/清理流程；真实两台电脑经服务器同步尚未实测。

保留的修复（0.13.1）
“核验连接中断/超时/额度受限”和“核验发现重要问题”分别显示，不再统一误报为重要问题尚未解决。已有队列中的中断记录会根据本地 workflow.json 恢复正确状态，原草稿保留。
检查未完成时显示“继续检查”，从本次已保存的草稿和资料段落索引继续独立核验，不重新解析 PDF，不重新生成整篇精读稿。采用设置中当前选择的检查通道、模型和强度；发现问题后仍按原上限自动修订、重新核验。历史生成记录与此次续检记录分开保存。
继续检查通过后，点击“保存笔记”保存到 Zotero；未完成检查时不冒充通过。导入按钮旁明确说明未启用的原因和下一步操作。
新增“刷新文件”：在本地编辑 Markdown 后可刷新当前窗口，并导入带人工修改标记的笔记。续检不会覆盖人工修改的 Markdown；手改稿不自动获得“已核验”结论。
续检前核对正文与纳入的补充材料是否变化；源文件变化时需要重新精读。当前修复已经对用户本次未完成草稿做只读兼容检查，没有改写、发送或导入用户草稿。

保留的更新（0.13.0）
精读入口与批量入口按 Zotero 父文献组织 PDF：每篇选择一个正文，补充材料默认不勾选。点击“设为正文”切换正文，勾选“作为补充材料参考”后才纳入该文件。选择父文献或其任一 PDF 都能查看同文献下的附件；独立 PDF 单独处理。
同一条文献下，内容完全相同的本地 PDF 只保留一个可选来源，不删除、不移动任何原附件。以文件 SHA-256 判断完全重复，不凭文件名或文件大小认定重复；尚未下载的文件不能确认重复，不会擅自排除。不同版本即使内容相近也不会自动合并。
Supplementary、Supporting Information、附录、补充材料等标题或文件名仅用于提示；多个不同正文候选或仅有疑似补充材料时，需要手动选择正文。自动精读遇到这种情况会停在“待选择正文”，不擅自调用模型。已知补充材料和完全重复的新附件自动跳过；启用开关不会扫描旧文献。
勾选补充材料后逐份解析，与正文合并生成和独立核验，仍只生成本次精读的一篇笔记。所选资料必须全部下载到本机；不会遗漏勾选但未下载的文件后宣称完成。所有已选文本合计最多 400,000 字符，超限停止而不截断。
合并阅读的证据区分正文 M 与补充材料 S1、S2 等，编号表示解析段落而非 PDF 页码。Markdown 和 Zotero 笔记列出阅读范围、来源及依据标记，source.json 保存各文件身份、用途和哈希，供后续 Wiki 入库核对。
跳过已处理项时同时比较正文、所选补充材料及文件内容；增加/去掉补充材料或修改其中的 PDF 都需重新精读。导入前也会核对已读取文件，补充材料变化、删除或移动后不能将旧结果当作当前资料的核验结果导入。
已有队列任务沿用原附件选择；如需更改，先停止该任务再重新选择。旧笔记和旧结果继续可读，不批量删除或覆盖。主动重新精读仍保留新旧版本，并非自动覆盖每篇文献的历史笔记。

保留的修复（0.12.1）
针对首次测试 Antigravity 时弹出终端：本机日志显示，CLI 首次初始化会另起后台自动更新进程，15 分钟内再次调用则跳过。插件现仅向自己启动的 Antigravity 子进程传入 AGY_CLI_DISABLE_AUTO_UPDATE=true，覆盖检测、模型目录、连接测试和正式精读/检查调用，阻止这条更新进程链。
环境变量只作用于子进程，不写入系统环境或 Antigravity 全局设置；继承已有登录和网络环境。用户单独启动 Antigravity 时的更新行为不变。此值已在本机 Antigravity CLI 1.5.1 实测有效；不会将“15 分钟内跳过更新”误判为开关生效。
该修复针对已定位的后台更新启动路径。它不保证模型秒回，也不改动现有 MCP 配置。

保留的修复（0.12.0）
Codex 模型目录查询和文本调用仅在本次进程中关闭 plugins、plugin_discovery_prefetch、shell_snapshot。进程追踪发现旧目录查询会拉起 Git/远程插件更新，这条额外进程链在新参数下不再出现；未修改用户全局配置或第三方客户端文件。Zotero 自身的进程接口已使用无窗口启动，未添加无效的 windowsHide 参数。
测试状态改为优先显示最近一次结果：最新的低档连通结果不会被较早的完整验证记录遮住。时间明确标为“上次”，测试中保留等待状态，取消/超时不会冒充成功；超时只说明未确认，不直接判模型不可用。
测试过程中暂时锁定模型和强度选项，仍可点击停止测试。模型回应耗时仍取决于 CLI 初始化、网络和服务端。
已观察到 Antigravity 会初始化全局 Zotero MCP。尝试的局部配置未能可靠禁止它，未将这些无效配置写入插件，也未更改全局 MCP。此次修复消除了已确认的 Codex Git 启动路径，不宣称已经彻底复现或消除所有偶发终端窗口。

保留的功能（0.11.0）
标题默认改为“精读笔记｜{author} {year}｜{title}”，对齐现有 Wiki 来源页的作者—年份—题目结构。{author} 为 Zotero 首位作者姓/机构名，{year} 是发表年。旧默认格式自动采用新默认；其他自定义命名保留。新增 {journal}、{itemKey} 占位符。规则应用于新生成结果，并保存命名快照；已有笔记不批量改名。
Markdown 新增 YAML frontmatter：title、reading_note_title、tags、keywords、author、created、updated、sources、source_ids、Zotero 条目/附件键、DOI 和 review_status。tags/keywords 复用现有条目标签，不伪造未提取的主题词；author 是生成工具，论文作者仍列于文献信息。来源身份明确区分个人/群组/本机文库。
同目录 source.json 保存 Zotero 原文引用与 PDF 哈希。sources 中 source.json 为同目录相对引用（source_base=same-directory）；workflow.json 保存核验状态和结果文件指纹。手改 Markdown 后，原核验状态不能自动套用于改稿，编译时需核对指纹。
这是 literature-reading-input，wiki_stage=input，不代表 Wiki 已完成编译。交给 DSH 后仍须读取原资料与现有 Wiki、维护相关主题/概念页，并把 sources 转为库中真实的 raw 清单路径；不直接复制为“已完成”的 Wiki 页面，不凭空生成关联。Karpathy 模式本身没有强制统一的标题模板，此处对齐的是你的科研库约定。
连接测试默认发送短文本并使用目录支持的较低档位，仅证明连通性；结果显示实际测试档位，不冒充当前高档或结构化输出已验证。勾选“结构化验证当前配置”后才使用上方选定强度并检查结构化输出。正式精读/核验配置不被测试改动。
快速测试最长60秒，完整测试最长180秒；按钮可再次点击停止，显示等待秒数和完成耗时。CLI 版本/帮助/登录检查按可执行文件路径、版本文件时间和大小短时复用；已有模型目录先展示，24小时内不因重开设置而重复拉取。真实模型回应仍受 CLI 启动、网络和服务端延迟影响，不保证秒回。

保留的功能（0.10.0）
笔记与 Markdown 开头增加文献信息：题目、作者、作者单位、通讯作者、期刊、发表日期、卷期/文章号、DOI、影响因子、JCR 分区、中科院分区或 CCF 等级、指标年份和来源。
题目、作者、期刊、日期、DOI 等优先读取 Zotero 父文献题录；无题录时，题目和作者可回退到有原文证据的提取结果。单位及通讯作者从解析文本提取，参与逐条独立检查与修订，不按作者排序猜测通讯作者或单位归属。
直接读取 Zotero One 使用的现有字段：文库编目（libraryCatalog）中的 IF/JCR 分区、索书号（callNumber）中的中科院分区或 CCF 等级。不调用 Zotero One 的联网更新接口，也不另行搜索期刊指标。请先在 Zotero One 更新条目，再开始精读。
指标年份只取 Extra 中明确标记的 JIF Year / Impact Factor Year / IF Year / 影响因子年份 / 影响因子年度；条目未记录则如实显示。论文发表年份、当前年份及 Zotero One 数据更新日期都不当作指标年度。
生成时保存题录与指标快照，之后 Zotero One 改动不会静默重写已有精读结果。正文的“检查通过”不代表本插件重新验证过第三方期刊指标。
旧七/九栏目结果继续可读，不重写已有人工笔记或知识库页面。

保留的功能（0.9.0）
本轮对齐你的 Karpathy LLM Wiki 的精读输入要求，新增三段前置分析：研究背景、为什么要开展这项研究、为什么能发表在这个期刊。随后保留设计、方法、主要结果、机制解释、局限与研究启发，共九栏。研究问题和假设合并进研究动机，避免重复栏目。
三个前置部分进入同一独立检查与修订流程。发表价值只能标为读后分析或材料不足，不能作为已验证的录用理由；没有期刊信息或定位依据时如实说明。
增加“作者解释”类型，与原文报告、读后推断分别保留。适用条件、待核数字和假设性质须写在对应观点旁边，不能只在全文末尾笼统提示。
0.8 及更早的七栏目结果仍可打开和手动导入，不补造新章节；新生成结果必须有完整九栏。已有自定义模板文字保留，新的必需栏目和核验规则仍生效；想查看新版默认提示可在模板页恢复默认后保存。
九栏目是你的科研精读约定，不是 Karpathy LLM Wiki 模式的通用强制格式。Wiki 后续仍需由模型结合原资料维护来源页、主题/概念综合、关联、分歧、索引和日志。
本轮只调整精读内容与旧结果兼容，不自动将笔记写入 DSH Wiki，也不改动第三方 dsh-kb 或既有知识页面。主笔记更新与 Wiki 入库衔接仍需下一步完成。

保留的功能（0.8.0）
精读与后台检查各有一个思考强度滑块，分别保存，生成后的自动修订沿用精读强度，复查沿用检查强度。
ChatGPT 通道的档位从本机 CLI 返回的模型能力中读取，按实际支持显示默认、低、中、高等档位。默认不强制覆盖模型设置；具体档位通过 model_reasoning_effort 传入。
Antigravity 的同一模型只显示一项，Low/Medium/High 从下拉型号中移到滑块，滑块调用目录中实际存在的对应型号，并传入一致的 --effort。不会构造目录没有列出的型号。
选择具体型号后才能调节；若只提供一个档位，滑块显示该档位并禁用。滑块每移动一格切换一个档位，不是连续的思考时间或 token 数量。
滑块可用鼠标或键盘方向键调节，修改后点击“保存模型设置”。更高强度通常需要更长时间与更多用量，并不保证结果一定更准确。
完整验证按通道、型号与强度分别记录；低档连通结果单独注明范围。换型号或强度后需要重新验证，过去其他组合的测试通过状态不会复用。

0.7 功能
1. 检查在后台进行，不再生成单独的检查报告或报告笔记。原有报告笔记不会被删除。
2. 发现不受原文支持、夸大、证据失配、漏检或重要遗漏时，将问题交给精读模型修订，再由检查模型在新会话里重新检查完整稿件。最多修订两轮，通常两次调用，有问题时最多六次调用。
3. 仍有重要问题或检查失败时，只保留本地草稿，不自动导入 Zotero。轻微表达或非必要数值建议不单独阻止完成。
4. 设置页分为概览、模型、PDF 解析、模板、输出；精读窗口以正文为主，批量与解析窗口采用统一样式。
5. ChatGPT 通过 Codex CLI 调用；Codex CLI 是调用通道。Antigravity 是另一个通道。精读与后台检查的通道、型号分别选择。
6. 普通连接测试只发送简短问候并显示回复；可选结构化验证检查 JSON 返回；模型目录本身不代表可用。状态按通道、型号与思考强度记录，显示测试时间，超过 24 小时或 CLI 版本变化后提示重新验证。

安装与首次配置
在 Zotero 的插件管理页，选择“从文件安装”，打开 zotero-reader-independent-0.12.0.xpi。与独立版旧版本使用相同 ID，更新保留密钥、缓存和队列历史。无需依赖原第三方插件。
1. PDF 解析：输入你自己的 MinerU API 密钥并保存。保存密钥不会上传文件；实际解析才上传所选 PDF。
2. 模型：插件自动发现本机 CLI 并读取模型目录。分别选择精读和后台检查模型，调节思考强度，点击各自的“测试连接”，再保存模型设置。两个阶段可以使用不同通道。
3. 模板：编辑生态与土壤微生物或通用论文模板，保存后生效。固定九个栏目和原文依据检查仍保留。
4. 输出：选择自动导入笔记，或先生成 Markdown、查看后手动导入。命名支持 {author}、{year}、{title}、{journal}、{itemKey}、{pdf}、{date}、{template}、{status}，下方提供预览。
两个通道使用各自本机 CLI 登录状态。程序路径留空自动查找；高级设置支持手动路径与每步 1–30 分钟超时。切换型号后须重新测试，不能用另一型号的成功状态代替。

日常使用
新增 PDF：在“概览”勾选启用自动精读。默认关闭，只处理启用后个人文库新添加的 PDF，等待文件稳定后逐篇运行；不补扫旧文献，不因普通修改或同步条目重复处理。
已有单篇：选择文献或 PDF，右键 Zotero Reader → 精读文献。已有草稿直接打开，新文献使用统一模板开始。
已有多篇：Ctrl/Shift 多选文献或 PDF，右键 Zotero Reader → 精读选中文献。核对附件列表，取消不需要的补充材料，再加入队列。不需要开启自动精读。
批量默认跳过已有处理记录且 PDF 未变化的条目，包含待核对草稿与待导入结果；需要重读时取消勾选跳过。父条目与 PDF 混选会去重，已有队列任务不重复加入。
暂停队列只暂停后续任务；停止本批次只影响该批成员。单篇失败不阻止后续文献。关闭窗口不停止任务。
关闭自动开关会停止正在运行及待处理的自动任务，不取消手动任务；已提交的 MinerU 云端任务可能继续。

笔记与 Markdown
自动模式：检查未发现重要问题后生成一篇精读笔记，不需要另点保存。
手动模式：从右键“打开精读结果”或队列“查看结果”打开，核对后点击“保存笔记”。编辑、刷新、打开结果文件夹及重新精读在“更多操作”中。
未解决草稿：保留 review-needed.md；检查中断时保留 draft.md。未修改的未通过稿不能导入。可重新精读，或人工修改相应 Markdown 后重新打开结果窗口，再导入带“人工修改稿（未重新检查）”标识的笔记。
人工编辑不会自动请求模型；原检查结论不适用于修改后的内容。已有笔记中的人工修改不会被覆盖，同次结果重复导入会复用笔记。主动重新精读是新一次结果，会保留新旧版本。
有父文献时生成子笔记；独立 PDF 生成带来源链接的独立笔记，不编造父文献元数据。
命名默认“精读笔记｜{author} {year}｜{title}”。日期采用北京时间；人工修改稿的状态标识不能通过命名模板隐藏。

精读结构与依据
研究背景 → 为什么要开展这项研究 → 为什么能发表在这个期刊 → 研究设计 → 分析方法 → 主要结果 → 机制解释 → 局限与替代解释 → 研究启发。
主要结果默认概括方向、条件差异与核心发现，仅在影响理解时保留必要指标。样本量、重复和处理条件等设计信息可保留。
区分原文报告、作者解释、读后推断和所提供文本未报告；未报告不等于不存在。相关关系不能直接写成因果结论，研究启发不能写成已经证实的研究空白。
生成、检查、修订均使用新的会话；检查模型重新查找原文证据，本地再检查段落、引句和观点覆盖。使用同一型号的不同会话不等于使用独立模型。
此流程降低错误风险，不能保证消除幻觉。检查对象是解析文字，未检查 PDF 图像、原始数据或外部文献。

本地文件（尚未导入时）
数据目录/zotero-reader-independent/readings/<运行标识>/：
- reading.md：检查未发现重要问题的结果。
- review-needed.md 或 draft.md：需要人工核对的本地稿件。
- draft.json、source-index.json、verification.json、internal/：结构化稿件、原文索引与每轮内部检查记录，供修订和追溯；不会另存用户可读报告或报告笔记。
- workflow.json：来源校验、模板快照、通道/型号、思考强度、修订次数、结果状态及已导入笔记信息。
解析缓存与队列也保存在本插件的数据目录。有效缓存复用不需再次上传，PDF 或解析设置改变后失效。
成功导入后按 0.14.0 的规则清理本次临时内容；saved-notes.json 和精简队列保留简短保存记录，正式成果在 Zotero 笔记中。后续 Wiki 入库应从已保存笔记和原 PDF 获取资料，不再假设 reading.md、source.json 或 workflow.json 永久存在。
底层调用记录在 codex-runs/；其中阶段答案不代表最终检查通过。model-health.json 只记录通道、型号、思考强度、时间、版本和成功状态，不包含凭据。

使用边界
MinerU 密钥独立保存在 Zotero Login Manager，只向 MinerU 官方接口发送；不写入普通偏好、代码或解析缓存。
本版只发送解析文字给模型，不发送图片；正文超过 400,000 字符会停止，不自动截断。实际模型上下文限制可能更小。
Codex CLI 使用 --ephemeral、read-only 沙箱与 never 审批，不加载个人 config.toml，关闭 shell/unified_exec 和 web_search。
Antigravity 使用 stream-json 与单次 strict 权限配置，拒绝命令、文件、网页和 MCP 工具；CLI 自身会话和日志由 Antigravity 管理，不保证无会话留存。终端沙箱仅在系统支持时生效。
两通道支持超时与取消；Antigravity 在 Windows 上终止本次调用所属进程树。
无自由提问功能，不自动覆盖、移动或删除已有笔记。真实 Zotero 服务器同步未在测试中执行。
MinerU 真实解析仍需用户输入密钥后验证；测试不使用用户论文或个人文献库。
ID：zotero-reader-independent@local。HTTPS .invalid 更新地址仅满足 Zotero 安装要求，当前需手动安装更新。
