# 0.14.27 — 归档超时、队列哈希预检与索引保护

日期：2026-11-09；本地源码和安装包已验证，未安装、未推送。基于 0.14.26，完整保留独立顶部摘要、中文筛选和默认关闭的多机协作。

## 单独补归档 / 更新推荐

移除分类请求写死的 `timeoutMs:60000`，沿用“模型 → 高级与检测信息 → 每步超时 / 分钟”的现有设置（1–30 分钟）。精读后复用后台检查建议的正常路径不变；连接测试的短问候超时也不受影响。原生合成引擎验证设置为 2 分钟时，Codex 和 Antigravity 实际接收的调用参数均为 120000 ms；超时和取消不会改变已有笔记或分类。未用真实模型等待两分钟，也未重跑云端 RPPL/QQZK。

## M2：队列预检不反复读取未变 PDF

仅对自动队列预检启用内存哈希缓存，按文件路径、大小、修改时间匹配，最多 512 项、60 秒有效期。普通选文、正式执行、保存前核对仍完整计算；缓存命中也响应取消，文件变化或过期重新读取。

预检缓存不能直接决定“已有笔记，跳过”或“重复附件，取消”：这些最终决定另做完整复核，开始自动精读前也重新确认正文选择。即便文件内容被同大小/同时间戳替换，也不能把预检摘要当作最终事实。

原生测试两份关联 PDF 连续五轮预检只有两次完整哈希，未扫描文库中的第三份无关 PDF；修改文件后重新计算，正式读取再次计算。这里的五轮为测试主动调用，不宣称生产环境每三秒扫描全库；并发满时原调度就不会固定每三秒轮询。

## M4：索引损坏不再被空内容覆盖

保护 `queue.json`、`saved-notes.json`、`classification-proposals.json` 和 `coordination-local.json`：

- 区分真正不存在、读取失败、JSON 损坏和不支持的基本结构。只有真正不存在才允许新建。
- 发生异常保留原文件；能读取时另存 `.preserved-…bak` 副本，禁止后续用空索引覆盖。
- 每次正常替换前，保留原有效字节至 `.last-good.json`，仍采用临时文件原子替换。
- 同一索引读写串行，读取结果与内部快照分离。运行期间外部修改或删除索引会阻断覆盖，不静默盖掉人工修复。
- 设置页明确显示异常；新精读、保存笔记、归档、生成缓存清理和附件整理入口受保护。允许查看原 PDF 和已保存笔记，已有草稿不删。已发出的外部模型调用不据此宣称全部撤销。

遇到异常不要删除索引重试。先保留原件和备份，核对实际笔记/任务后修复，并重启重新加载；不自动采用可能过时的备份。看门狗若需要续检，应使用插件任务入口，不应直接覆盖运行中的索引。
