# 在另一台 Windows 电脑继续

## 开发源码

解压整个交接包到独立目录。`project/` 的源码和当前 `release/` 的 XPI 对应 0.14.24；无需旧电脑的同名用户名或盘符。

旧环境已确认：Zotero 10.0.7、Node.js 22.18.0、Python 3.13.5、Antigravity CLI 1.5.1。模型目录和 CLI 行为会变化，到新电脑后应重新检测；不要把旧测试时间当作新机可用性的证明。

先运行不联网的检查：

```powershell
# 当前目录为交接包根目录
python tools/check.py --baseline
```

以后修改源码，再运行 `python tools/check.py`。产物在 `.work/`。该命令会检查 JS/XML、运行所有 `*.test.cjs`，并调用 `project/build.py` 打包；不启动 Zotero，也不调用真实模型。

单独构建：

```powershell
python project/build.py --output .work/zotero-reader-independent-dev.xpi
```

仓库从 0.14.1 源码快照开始记录版本。新电脑克隆整个仓库后从根目录开发；无需复制旧电脑的整个 Codex 工作区。`.gitignore` 排除测试缓存和依赖目录。

## CLI 自动查找与检测状态

0.14.2 会从显式配置、进程 PATH、npm 默认位置和 Windows 返回的 LocalAppData 中查找 Codex；桌面应用构建目录动态枚举，不复制旧机路径。Antigravity 也从当前系统用户目录查找。显式路径无效时直接提示修正，不静默切换到其他程序。

修改路径后需重新检测和测试。旧版成功记录缺少程序身份信息时不再直接显示绿色；程序缺失、检测失败或取消测试时不能沿用旧成功。连接恢复不等于模型目录刷新，缓存目录会明确标注待刷新。

## 使用插件所需配置

1. 安装 Zotero，登录同一个 Zotero 账号，等待文献和笔记数据同步。
2. 按你原来的坚果云/WebDAV 设置启用 PDF 文件同步。已导入的笔记走 Zotero 数据同步，不依赖本插件另传 Markdown。[同步机制说明](https://www.zotero.org/support/sync)
3. 在 Zotero 中安装 `release/zotero-reader-independent-0.14.24.xpi`，重启。
4. 在新电脑安装并登录要用的模型 CLI；插件中重新检测通道和型号。若旧配置保存了程序绝对路径，应改为新路径或留空自动寻找。
5. MinerU 密钥由用户在新机插件设置中输入。开发包不迁移 Login Manager 或 CLI 登录文件。

不要把整个 Zotero 数据目录（包含 zotero.sqlite）直接放进坚果云同步目录；继续使用 Zotero 内置的数据/附件同步。[Zotero 官方说明](https://www.zotero.org/support/sync)

本次没有迁移文献库、Wiki、未导入草稿和本地核验状态。已有笔记随同账号同步后可阅读；0.14.1 会识别新版笔记附带的来源指纹，并在批量/自动入口避免重复处理。真实双机同步仍需验证，见 HANDOFF.md。旧机尚未导入的稿件若要成为跨机成果，应先在旧机完成检查和导入；不要同步临时工作目录。

## 0.14.5 工作流设置

精读只使用统一模板；旧模板 ID 和草稿兼容保留。默认同时处理 2 篇，每篇每轮一次完整核验，不再拆组。概览提供“发现问题后自动修订”开关和 1–5 次上限，默认 2 次。关闭后仍检查，只不自动改稿。返工达到上限仍未通过时可在该任务旁继续修订/检查，不需要删除文献；网络或格式中断保留原稿，续检不重新解析 PDF。

PDF 默认采用中英兼容语言包，无需手选。官方 `ch` 同时支持中文、英文、繁体；高级选项保留英文覆盖，不向接口发送 `auto`：[MinerU 语言说明](https://mineru.net/doc/docs/index_en/#language-value-reference)。

成功保存的新核验笔记加 `AI精读` 标签，不替用户设置人工已读状态。主笔记开头可显示一条完整且已检查的主要结果，不另建摘要或核验报告笔记。

归档方式在概览中选择：新版默认自动归档，也可改为逐篇确认或不自动归档。自动模式在笔记保存后使用本轮核验建议添加分类，并移出原待处理归属；其他已有分类保留。不明确或失败时留在原处，不强行移动。旧待确认建议仍需手动处理；手动模式沿用勾选及确认操作。

## 阅读、核对与导入

安装后重启 Zotero，再重新打开结果窗口。检查中无需刷新，状态会自动更新；待修订时可展开问题查看草稿/原因/原文片段，点击“自动修订并复查”；检查通过后点击“保存笔记”，保存后点击“查看笔记”。如果设置为自动保存，完成后直接显示已保存。

需要自己修改时，点击“编辑草稿”，在窗口内修改并保存，然后选择“导入人工修改稿”。这一步不重新请求模型，笔记会明确标为未经再次核验的人工稿；若文件已在别处改动，会拒绝覆盖并提示重新载入。原 PDF 不改。

“更多操作”中保留编辑、归档、刷新结果、打开文件夹、重新精读及高级的重新解析正文 PDF。未完成且未保存笔记的任务不能归档；当前完成笔记（含用户确认导入的人工稿）可归档，人工稿仍明确标为未经再次核验。旧建议必须与当前笔记一致，分类改变前先保存明确确认记录。已保存任务和结果窗口上的“归档／添加分类”可重新打开独立窗口，不需要再次精读。设置页不再承载具体文献的归档卡片。多篇建议在一个窗口中依次处理；关闭/稍后处理会保留建议，未经确认不改变分类。

## 指定分类触发自动精读

安装 0.14.3 后，在“概览 → 监听分类”选择 `Notero文献库 / 00_新导入文献`，再启用自动精读。分类选择立即保存；只处理此后直接加入该分类的文献或其新 PDF，不补扫已在分类中的条目，不包含子分类。未改变选择时保留原“全部新增 PDF”行为。

移动已有文献进入范围可以触发，普通字段修改和服务器同步不会触发。移动出范围或改选分类将停止旧范围的自动待处理任务；不会删除原 PDF、已有笔记或草稿。已有条目需要立即处理时仍使用明确的手动单篇/批量入口。

## 原生 Zotero 隔离测试（需要时再做）

基础检查通过后，只有需要验证原生界面/宿主 API 时才做这一项。它会出现测试窗口；不要在用户不希望桌面被操作时运行。默认测试使用合成数据和模拟服务，但会检查本机 Codex 可执行程序版本，因此需可找到 Codex CLI。

```powershell
python project/tests/prepare_smoke.py

# 改成新电脑 Zotero 的实际安装路径
$zoteroExe = 'C:\Program Files\Zotero\zotero.exe'
$testProfile = (Resolve-Path -LiteralPath '.\zotero-reader-smoke-profile').Path
$testData = Join-Path $testProfile 'data'
$env:MOZ_NO_REMOTE = '1'
Start-Process -FilePath $zoteroExe -WindowStyle Hidden -ArgumentList @(
  '-no-remote', '-new-instance', '-profile', ('"' + $testProfile + '"'),
  '-datadir', ('"' + $testData + '"'), '-purgecaches', '-ZoteroDebugText'
)
```

检查 `zotero-reader-smoke-profile/smoke-result.json`，须有 `completed: true` 且全部测试 `ok: true`；如有 `smoke-fatal.json`，先定位失败。原生测试默认结束后自行退出，启动器的退出不等于测试完成。

`--live-engines`、`--live-reading`、`--live-agy-startup` 会调用真实模型，不是离线测试；只在明确需要时使用。`--visual` 和 `--visual-attachments` 打开隔离预览，不请求模型。

`--saved-cleanup` 只运行原生笔记保存、识别与清理检查。可在启动测试 Zotero 前设置 `$env:MOZ_HEADLESS='1'` 并添加 `-headless`，全程无需控制桌面。目录联接测试需要运行环境允许在隔离目录创建联接；沙箱报 EPERM 时应按工具授权机制处理，不应删除测试或将其记为通过。

CLI 专项原生回归：`python project/tests/prepare_smoke.py --cli-detection`。它生成 `.work/cli-detection-profile`，启动命令中的 profile/data 路径相应改用这个目录，保持 `MOZ_HEADLESS=1` 和 `-headless`。结果为 `cli-detection-result.json`，要求 `completed: true` 且所有 `ok: true`；检查 `cli-detection-fatal.json`。只使用合成 CLI，不发真实模型请求。不要在仍运行的隔离进程上重写 profile；重复测试前保留旧结果，并确认没有旧的 fatal/result 文件被误认作新结果。

分类专项：`python project/tests/prepare_smoke.py --collection-watch`，profile 为 `.work/collection-watch-profile`，结果为 `collection-watch-result.json`。只使用合成条目，并测量原生设置页控件布局。

真实 CLI 专项：`python project/tests/prepare_smoke.py --live-cli-status`，profile 为 `.work/live-cli-status-profile`，结果为 `live-cli-status-result.json`。此项会读取本机既有 CLI 登录并发送每通道一次简短问候；仅在用户明确授权真实连接检测后运行，不发送论文，不复制旧机凭据。

完整新工作流回归：`python project/tests/prepare_smoke.py --workflow`，使用 `.work/workflow-profile`，结果为 `workflow-result.json`。该脚本模拟解析和 CLI，测试双层并发、返工、标签、确认归档和队列直接续检；不会发送真实文献或请求真实模型。创建/准备 profile 时会清除该测试的旧结果文件，运行前仍需确认没有旧测试进程占用目录。

阅读界面专项：`python project/tests/prepare_smoke.py --reader-ui`，使用 `.work/reader-ui-profile`，结果 `reader-ui-result.json`。原生验证包含状态实时更新、顺序核验、修订、导入、人工编辑冲突保护、未完成归档拦截及 700px 布局，并以原生 Gecko 渲染捕获截图；不请求真实模型。

多分类归档专项：`python project/tests/prepare_smoke.py --archive-ui`，使用 `.work/archive-ui-profile`，结果为 `archive-ui-result.json`。验证手动导入触发、推荐与手选分离、多选、默认保留/明确移出、失效目标拒绝和原生保存失败回滚，使用合成文献及模拟模型，并捕获实际界面截图。

隔离测试额外设置 `extensions.zoteroWinWordIntegration.skipInstallation=true` 和 `extensions.zoteroOpenOfficeIntegration.skipInstallation=true`，避免首次测试 profile 触发内置文字处理软件插件安装提示；这些设置仅用于测试 profile。

隔离测试配置同时关闭 `extensions.zotero.firstRun` 和当前宿主使用的 `extensions.zotero.firstRun2`，避免新 profile 自动打开 Zotero 欢迎网页；不要修改个人 profile 来解决测试副作用。

保存精简测试结果后，只清理确认属于本开发目录的隔离 profile。不要按 `zotero.exe` 进程名批量关闭个人 Zotero，不要删除真实数据目录或 Wiki。

## Wiki / Obsidian

若需要在新电脑继续使用 Wiki，另外迁移用户正式知识库中的 Markdown、原始资料和配置；开发包不包含这些内容。不要把 `project/`、`.work/`、测试文库或依赖放进知识库。

下一阶段的入库应以已经保存的 Zotero 精读笔记和原 PDF 为依据。插件清理本机临时 Markdown 不应删除已正式进入 Wiki 的文件，也不应要求为了 Wiki 保留全部模型运行日志。

## 0.14.8 设置与验证

精读和后台检查独立配置，归档建议随检查结果一起返回，无需第三个模型配置。保存笔记后仍由你确认分类。普通连接测试发送一句问候并显示回复；勾选结构化验证才验证当前强度的 JSON 输出，模型自述不作为型号依据。

`python project/tests/prepare_smoke.py --settings-ui` 准备 `.work/settings-ui-profile`，使用模拟模型检查对齐、按钮状态和回复显示。原生启动沿用上面的隔离/headless 参数，不加载个人文库。

## 0.14.9 标签排版

安装后重新打开尚未导入的结果窗口，未人工编辑的旧稿将去除重复标签，无需重新精读；原始 Markdown 和已保存笔记不自动改写。`python project/tests/prepare_smoke.py --attribution` 准备 `.work/attribution-profile`，使用合成数据检验预览、人工稿保护和笔记导入，无模型请求。

## 0.14.10 完成归档

模型推荐多项分类，也可提出已有归属的移出建议，但全部由你选择。已有分类默认保留，未新增也可完成；只想退出待处理时单独勾选移出。旧笔记点击“更新推荐”即可，不用重新精读。`--archive-ui` 覆盖四项建议、主动更新、无新增完成、只移出待处理、选择性调整及事务回滚。

## 0.14.11 一键清理

笔记保存并确认归档后，点击概览的“清理已完成任务”，一次处理安全可删的生成缓存和队列记录。处理中、未确认或修改稿会保留并说明原因；PDF、笔记和分类不变。保留防重复识别信息，清理不会自动重新精读。

`python project/tests/prepare_smoke.py --completed-cleanup` 准备 `.work/completed-cleanup-profile`，使用合成数据验证按钮、缓存删除、队列重载和防重复。仍须使用隔离 data/profile 参数。

## 0.14.12 页面脚注

作者单位等信息可能保存在结构化解析脚注中。新版在发送精读/核验前自动补读并去重；有效旧缓存可复用。旧稿不会自动改变，安装重启后选择“重新精读”才会使用补全输入；不会覆盖旧稿，但会调用模型。仅刷新文件或继续旧检查快照不会补全原输入。

`python project/tests/prepare_smoke.py --footnote-source` 准备 `.work/footnote-source-profile`，使用旧式合成缓存和模拟模型核对输入范围、返工、格式错误保护及笔记保存，不发送真实论文。

## 0.14.13 简洁入口

日常选中文献后使用右键 Zotero Reader → 精读文献；多选自动进入批量选择器，无需先单独解析。已有草稿直接打开，查看已保存结果可用打开精读结果。队列每篇只展开主要按钮，其余在更多；需要重新生成旧稿时在结果窗口更多操作 → 重新精读。

0.14.14 仅修正分类名称与理由相连的空格，安装重启后重新打开归档窗口即可，不需重新精读或更新推荐。

## 0.14.15 批量语言筛选

多选后打开精读入口，默认同时启用跳过已有精读结果和跳过中文论文。列表按 Zotero 语言字段显示英文/中文及原值；未标注的请核对，不会按中文笔记猜测语言。取消跳过中文可在本批处理中文。普通手写笔记不会当作已精读，建议先抽查少量再扩大批次。本选项不控制自动监听或单篇主动精读。

`python project/tests/prepare_smoke.py --batch-language` 准备 `.work/batch-language-profile`，使用合成文库核验语言、已有结果、手写笔记保护及元数据变更，不请求模型。

## 0.14.16 精简笔记

安装重启后，新保存的笔记保留正文和来源链接，不再自动追加长篇原文依据附录。尚未保存的旧草稿直接保存即可采用新格式；已有笔记不自动改写。完整核验和返工仍按原规则进行。

## 0.14.17 自动归档与旧稿清理

等待当前任务结束后再安装并重启。之后的新完成任务默认自动归档；旧待确认建议不会被批量补执行。“清理已完成任务”现在可识别能由历史记录逐字重现的旧中间稿；无法确认或确实修改的文件仍保留，并显示文件名。`--auto-archive` 为合成自动归档专项，`--completed-cleanup` 包含旧中间稿兼容回归。


## 0.14.18 一键保存与停止后续检

等待当前运行任务结束后安装并重启。设置中的任务队列有待保存结果时显示“一键保存笔记（N 篇）”，点击后逐篇保存已通过检查且 Markdown 未修改的结果；不会重新解析或调用模型。停止、待复核、编辑中的任务不批量保存，文件变更或单篇失败会跳过并显示原因，其余继续。保存后沿用现有归档设置和成功保存后的缓存清理规则；清理已完成任务仍用于归档完成后的历史收尾。

有完整草稿的已停止任务显示“继续检查”；只有主动点击才恢复检查，不重跑原始精读。生成未完成的任务应从普通精读入口重新开始。旧记录没有取消来源时明确说明未知，不能推断一定是用户点击；新记录区分单篇、批次、全部停止、插件关闭或监听范围变化。


## 0.14.19 一键继续

任务队列右上有“一键继续（N 篇）”时，点击即可把现有可续检草稿加入队列，同时恢复队列。中断/停止的稿件继续检查，待复核稿件使用已有的自动修订复查流程；遵守同时处理篇数设置，不重跑解析或初稿生成。已保存笔记和正在编辑的稿件不入队；缺少完整草稿、人工修改及排队后发生的变化会保留并显示原因。

“暂停队列”只阻止新任务启动，正在运行的任务可以完成；再点“继续队列”运行剩余排队任务。队列操作中的“停止任务”会停止运行任务及等待续检的任务。重启后未启动的续检请求不自动重放，需要主动继续。检查通过后沿用原有自动保存/手动保存设置，不改变归档规则。


## 0.14.20 单按钮开始／全部暂停（替代 0.14.19 的两个控制）

任务队列右上只保留一个主控制按钮：空闲或暂停时为“开始”，点击统一继续已有草稿及排队任务；运行时为“全部暂停”，再次点击会中断当前请求并暂停后续任务。暂停收尾期间显示“正在暂停…”且暂时禁用，结束后恢复“开始”。原有独立“一键继续”和全局“停止任务”入口已移除；单篇更多操作仍可用。

已有完整草稿从核验继续，待修订稿保留修订意图；初稿还未生成完成时，下次开始重新执行未完成的生成步骤，旧记录保留。不能承诺在同一次模型输出的中间字符继续。已提交的笔记事务不会撤销；后续保存和归档等待或取消本次操作，归档暂停后可使用保留建议继续，不重复生成笔记。


## 0.14.21 已有分类建议与批量正文定位

已有其他分类的文献，在本轮精读核验提出新增或移出建议时，先保存笔记，再展示理由，不直接改动原归属。可以点击“按建议处理（新增 X，移出 Y）”一次采纳当前这篇的已展示建议；也可以勾选部分分类后确认，或稍后决定。是否移出待处理分类仍按下方勾选，其他原分类保留，不扫描历史笔记补归档。未分类的新文献继续遵守自动归档设置。

批量界面若有选中的文献缺少明确正文，主按钮显示“选择正文（N 篇待确认）”并保持可点击。点击会滚动并聚焦具体文献的正文选项；选择一个正文，或取消勾选该文献，再继续。全部确认后才显示“加入精读队列”，不会自动猜选正文或默默丢掉未确认的文献。中文过滤仍生效，已解决的提示会刷新。


## 0.14.22 自动识别正文与版本

用户最新要求替代“多个正文版本必须手选”：优先已发表的正式版本，其次接受稿；同级版本稳定选择一份，仍可手动改选。补充材料默认不参与精读，需勾选后才会送入模型；字节相同的重复 PDF 不重复读取，也不删除原附件。

识别优先复用与当前 PDF 指纹匹配的已有解析缓存，否则调用 Zotero 内置 PDFWorker.getFullText(itemID, 2, true) 提取前两页文字。按首页题名、Supporting Information、Accepted Manuscript、Version of Record 等文字线索判断，不截图、不调用视觉模型、不新增 MinerU 上传。`.sapp.pdf` 纳入补充材料名称提示。

本地识别设大小和等待限制；扫描件没有文字层、文件未下载或解析失败时，沿用附件名称线索并显示来源。没有版本依据显示“版本未明确”，不能把自动择一视作已确认正式版。只有补充材料而无正文候选时仍提示指定正文。显示的识别来源区分本地解析、已有解析结果、附件名线索；手动选择不被刷新覆盖。


## 0.14.23 重复附件与题录归属整理

多选需要检查的文献，打开“精读文献”的附件窗口。发现问题时显示“附件整理”，仅作用于本批勾选的文献；不后台扫描或自动清理全库。先暂停运行任务并等待保存结束，再整理附件。

- “一键清理重复 PDF”：只按同一父题录内相同 SHA256 判断重复。优先保留带批注、笔记、标签、关联或任务引用的副本；可安全清理的空副本移入 Zotero 回收站，不永久删除或改写 PDF。不同版本不当重复，引用无法确认时保留。
- “一键修复已确认归属”：根据 PDF 首页 DOI 查找同一文库唯一的正确已有题录，目标在 PDF 下方显示。迁移保留原附件 key、文件路径及批注；仅链接该 PDF 的专属批注笔记可一起迁移，正文不改。混合来源笔记不自动移位，精读结果或未完成草稿引用的附件保留待核对。不自动新建/合并题录，不改变分类或题录字段。
- 若目标已有字节完全相同的 PDF：无保护信息的错挂副本直接回收；错挂这一份带批注/笔记时保留它并迁移，清理目标中的空副本。两份都带保护信息时均保留。已有 PDF 尚未下载、内容不同或目标不唯一时不据此回收。

首页 DOI 明确不符的 PDF 会被排除出当前题录正文/补充材料，并在真正生成、续检或保存前再次检查。识别依赖可提取文本或有效解析缓存；缺少 DOI、文字或唯一目标时不会猜测迁移。

整理记录保存在本机插件目录 attachment-maintenance/，只记录身份、哈希、原/新父题录及回收项，不包含论文全文。回收站操作可恢复，链接附件的外部文件不会直接删除。磁盘空间不会因仅移入回收站立即释放。

数据事务先完成，再统一通知 Zotero 刷新。Zotero 10.0.8 的分类树刷新在隔离测试中可能等待选择事件；刷新未及时结束时，插件仍准确显示已完成的数据结果并提示重新打开列表，不回滚已完成操作或重复清理。原生回收站/文库切换也已测试。


## 0.14.24 紧凑设置布局

设置页卡片与字段间距缩小。监听分类的刷新按钮移到标签右侧，模板标签和选择器同行；同时处理篇数、自动修订及最多次数组成一行，数字框为短输入。空间不足时按组换行，修订开关和次数仍在一起。控件取值范围、配置键和保存方式不变。

本机隔离原生检查覆盖 1200、920 和实际最小 800px 窗口，以及模拟 410px 宽面板。没有横向溢出，修订开关和模型测试反馈保持正常；同宽自动精读卡片高度约减少 40%。没有在个人 Zotero 中改变设置；安装后重启并重新打开设置页即可。
