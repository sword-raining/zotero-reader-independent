# 0.14.12 — 补读解析结果遗漏的页面脚注

日期：2026-11-08；本地构建，未自动安装或推送。

- 原因：MinerU 已在结构化结果中保存页面脚注，但 full.md 可能省略这些内容；旧插件只读取 Markdown，导致两个模型同时看不到作者单位。
- 新增只读文本组装层，读取 content_list、content_list_v2 及 layout 中明确标注的 page_footnote，补入 Markdown 缺失的脚注。正文已有内容、不同结构格式的同一脚注不重复；不把普通页眉、页脚或页码混入正文，不对原缓存写回。
- 自动队列和直接阅读入口均采用组装后的输入。正文与用户选中的补充材料分别补读，保持来源段落编号；补充材料仍需明确选择。生成、核验和返工都使用同一份 source-index。记录脚注页信息、文件指纹和组装文本指纹，便于追溯。
- 生成及核验提示明确检查首页、文末和补入脚注。对于“未明确标注”的文献信息也反查原文；单位名称存在但作者对应关系不清时，可列单位，不将其当作未提供。损坏、异常变化或超限的结构化结果会中止，不静默忽略后标为完成。
- 复用有效旧解析缓存，不要求重新上传 PDF。既有稿件、已保存笔记及旧续检快照不自动改写；对于已使用缺失文本生成的旧稿，请安装重启后选择“重新精读”，从完整输入重新生成和核验。该操作会请求模型；缓存有效时不重新请求 MinerU。旧草稿保留。

验证：200 项自动检查、6 项隔离 Zotero 10.0.8 原生检查通过，使用合成 PDF/缓存与模拟模型，零网络请求。实际覆盖旧缓存补读、正文默认范围、显式补充材料、精读→核验→返工→复查、直接阅读入口、同长度损坏 JSON 拒绝及作者单位的原生笔记保存。

另对用户指出的那篇文献现有缓存做了只读兼容验证：原 Markdown 中的五个单位标识均缺失，补入一条第 1 页脚注后五个标识全部存在，脚注原文和缓存文件字节保持不变。没有改动或重跑真实稿件，没有用真实模型验证该稿最终提取效果；完整 PDF 解析准确性及双机同步也不属于本轮证明。

证据：`validation/native-footnote-source-0.14.12.json`、`validation/local-footnote-cache-0.14.12.json`。未复制真实论文全文到仓库或安装包。
