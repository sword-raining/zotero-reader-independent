# 多机协作：范围与验证边界

0.14.26 提供默认关闭的协作模式。两台、三台或更多机器可对重叠队列领取不同文献；共同处理同一 Zotero 账号的个人文库。当前没有真实坚果云和物理三机联调结果，不能把本地模拟服务的测试当作真实云端保证。

## 启用

1. 所有参与端安装支持协作的同一新版插件，各自在本机登录 CLI、配置 Zotero 数据同步与相同的 HTTPS WebDAV 存储。不要复制旧机凭据或整个 Zotero 数据目录。
2. 在“概览 → 多台机器一起精读”点击“检测并开启多机协作”。每台分别开启。检测只操作独立目录中的随机小测试文件，验证条件新建、三个并发条件更新只有一个成功、过期版本不能覆盖；检测失败不启用，不退回无保护运行。
3. 在任意分类右键单篇/批量精读仍然有效。手动选择属于本机队列，不把整批本地任务/草稿复制到另一台；不同端队列重叠时通过共享领取记录协调。开启协作且指定监听分类后，同步来的新加入通知也可参与领取。不会补扫此前已有条目。
4. 等待另一端时本机继续处理其余任务；保存笔记同步到本机后可识别并跳过。未开启协作的旧版实例不会遵守领取记录，因此不能混用后声称已防重。

## 实际存储与安全边界

- 在现有 WebDAV 基目录旁建立 `zotero-reader-coordination-v1/`，与 Zotero 附件目录分开。远端只有哈希任务/输入身份、随机设备/领取令牌、状态、时间和已保存笔记 key；没有标题、论文全文、草稿、核验报告、解析缓存或密钥。
- 本机通过 Zotero 的 WebDAV 密码接口使用已经保存的本机凭据；不导出、不写入项目，也不修改全局 CLI 设置。仅支持 HTTPS，拒绝重定向；请求日志不输出正文或凭据。
- 以服务端时间判断 12 分钟租约，每 3 分钟续约。断网、限流或失去处理权时停止后续请求，保留本地稿件；已发送到外部模型的调用不保证能撤销所有消耗。没有保存中的任务可以在失效后由其他端领取。
- 保存前条件切换为不自动过期的保存保护，防止旧进程恢复后再写一份。明确回滚则保留原机草稿；重启后根据本机事务结果核对：已保存的登记完成，没有笔记的保留为原机待续草稿，身份异常/多份/已删除笔记保持待核对。
- 分类调整另有条件写入保护，正常成功或明确回滚后释放；进程在分类写入中崩溃的远端保护不会被另一台按超时强行覆盖，此类情况需核对原机分类记录。暂未提供跨端一键强制接管归档的功能。
- 未导入或需要继续检查的草稿留在原机；暂停不会把草稿迁移到别的电脑。已完成的远端记录不自动删除，也不自动开启第二版精读；附件版本不同先核对。主笔记版本管理仍是后续工作。

## 验证

308 项自动检查含三客户端竞争、失效接手、旧令牌阻止保存、保存保护不随时间过期、损坏记录保护、失败响应、服务器忽略条件写入时拒绝开启、保存重启恢复和中文/摘要检查。

三套独立 Zotero 10.0.8 原生进程连接仅绑定 127.0.0.1 的合成 WebDAV 服务：三个不同设备同时持有三篇不同文献，恰好各写一份笔记，峰值并发 3；模拟 Zotero 笔记同步后不重复运行。此处同步是合成数据注入，不是经过 Zotero/坚果云服务器的真实跨机同步。所有真实模型、真实云解析、真实云 WebDAV 请求均为 0。

可运行：`python tools/run_multidevice_smoke.py --zotero <本机 Zotero 可执行文件>`。它只创建项目 `.work/` 下的隔离文库，不读取个人凭据，不触碰个人进程；程序路径由当前电脑提供。

协议依据：[HTTP 条件请求与 If-Match / If-None-Match](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1)、[Zotero 数据和附件同步](https://www.zotero.org/support/sync)。坚果云有请求频率限制，遇到限流必须停下重试，不能绕过领取；当前官方额度说明见[坚果云 WebDAV 说明](https://help.jianguoyun.com/?p=2064)。
